# P Plan in Osaka

가고 싶은 장소와 여행 스타일을 고르면, 실제 도보 동선을 반영해 오사카 여행 일정을 만들어주는 서비스입니다. **Y-AI 메이커톤에서 팀 14가 약 4시간 동안 제작했습니다.**

[서비스 바로가기](https://p-plan.replit.app/)

[발표 자료 다운로드 (PPTX)](docs/Osaka_Planner_Team14_Updated.pptx?raw=true)

위 링크에서 메이커톤에서 만든 버전을 체험할 수 있습니다.

## 왜 만들었나요?

가고 싶은 곳은 많은데, 어느 날 어떤 순서로 방문할지 정하려면 지도에서 장소마다 이동 시간을 찾아봐야 합니다. 같은 장소를 골라도 하루를 촘촘히 채우고 싶은 사람과 현지에서 즉흥적으로 움직이고 싶은 사람의 일정은 달라요. P Plan은 내가 고른 장소를 출발점으로 삼아, 여행 스타일과 실제 이동 시간을 함께 반영합니다.

## 주요 기능

- **내가 고른 장소로 일정 만들기** · 날짜와 활동 시간을 설정하면 여행 일수에 맞춰 관광지를 분산합니다. 필수 방문 장소와 지정한 날짜·시간을 반영하고, 일정에 들어가지 못한 장소는 후보로 남깁니다.
- **무계획력으로 일정 밀도 조절하기** · 낮게 설정하면 선택한 장소를 더 많이 일정에 배치하고, 높게 설정하면 현지에서 자유롭게 움직일 시간을 더 많이 남깁니다.
- **지도에서 실제 도보 경로 확인하기** · Google의 도보 경로와 예상 이동 시간을 날짜별로 확인할 수 있습니다.
- **일정 수정하기** · 방문 순서나 체류 시간을 바꾸면 일정과 지도 경로를 다시 계산합니다. 추가 여행 조건은 자연어로 입력할 수 있습니다.

## 사용 방법

1. 여행 날짜와 하루 활동 시간을 설정합니다.
2. 가고 싶은 관광지를 고르고 무계획력을 조절합니다. 꼭 가고 싶은 장소나 정해진 방문 시간이 있다면 함께 지정합니다.
3. 생성된 날짜별 일정과 지도 경로를 확인하고 방문 순서나 체류 시간을 수정합니다.

## 구현 방식

| 구성 | 역할 |
| --- | --- |
| 규칙 기반 로직 | 날짜별 장소 배치, 일정 조합과 시간 계산 |
| Google API | 관광지 정보, 실제 도보 경로와 예상 이동 시간 |
| OpenAI API | 자연어로 입력한 여행 조건 해석과 일정 재생성 |

## 로컬 개발 시작하기

메이커톤 이후에는 팀 저장소를 각자 GitHub 계정으로 포크해 원하는 기능을 추가하거나 개선할 수 있습니다.

1. 팀 저장소에서 **Fork → Create fork**를 누릅니다.
2. 내 계정으로 복사된 저장소에서 **Code → HTTPS** 주소를 복사합니다. 터미널에서 아래 명령을 실행합니다. `내-GitHub-ID`는 본인 계정으로 바꿉니다. 포크 이름을 변경했다면 복사한 URL과 해당 폴더명을 사용합니다.

   ```bash
   git clone https://github.com/내-GitHub-ID/p_planner.git
   cd p_planner
   git switch -c feat/my-improvement
   ```

3. 내려받은 폴더를 Cursor, VS Code 또는 Codex에서 열고, 앱을 실행할 터미널이나 개발 도구의 실행 설정에 아래 환경변수를 등록합니다. 포크에는 기존 Replit Secrets가 포함되지 않으므로 각자 사용할 키와 세션 비밀값을 설정합니다.

### 환경변수

| 환경변수 | 용도 |
| --- | --- |
| `GOOGLE_MAP_KEY` | Google 지도 및 장소·도보 경로 조회에 사용하는 API 키 |
| `OPENAI_API_KEY` | 자연어 여행 조건을 처리하는 OpenAI API 키 |
| `SESSION_SECRET` | 기존 배포 설정에 있던 값. 현재 저장소 코드에서는 참조하지 않습니다. |

API 키와 세션 비밀값은 로컬 실행 환경에만 설정하세요. 프로젝트에서 `.env`를 지원해 그 파일을 사용하는 경우, 실제 값이 담긴 `.env`는 Git에 올리지 않습니다.

### 설치 및 실행

Replit 개발 환경과 같은 Node.js 24와 pnpm을 사용합니다. 저장소 루트에서 의존성을 설치합니다.

```bash
pnpm install --frozen-lockfile
```

로컬에서 화면과 API를 연결하려면 `artifacts/osaka-ilttan/vite.config.ts`의 기존 `server` 설정에 아래 항목을 추가합니다.

```ts
proxy: { '/api': 'http://localhost:3001' },
```

macOS·Linux 또는 Windows의 WSL에서 터미널을 두 개 열고, 각각 저장소 루트에서 다음 명령을 실행합니다. API 키는 API 서버를 실행하는 터미널에 설정합니다.

```bash
# 터미널 1 · API 서버
PORT=3001 pnpm --filter @workspace/api-server dev

# 터미널 2 · 웹 화면
PORT=5173 BASE_PATH=/ pnpm --filter @workspace/osaka-ilttan dev
```

브라우저에서 [http://localhost:5173](http://localhost:5173)을 엽니다.

수정한 내용은 작업 브랜치에 커밋하고 내 포크에 푸시합니다. 팀 저장소에도 반영하고 싶다면 내 작업 브랜치에서 팀 저장소로 Pull Request를 열면 됩니다.
