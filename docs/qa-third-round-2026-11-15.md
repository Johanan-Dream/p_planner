# 피플랜 3차 개선 — 실제 검증 기록

기준: 2026-11-15 한국시간. 같은 기존 프로젝트를 수정했으며 이 작업에서 공개 게시를 실행하지 않았다. Preview의 API 및 브라우저를 대상으로 확인했다. API 키 값은 기록하지 않았다.

## 구현 범위

- Google Places New의 실제 `regularOpeningHours` / `currentOpeningHours` / `websiteUri`를 사용한다. 누락된 필드는 확인 필요로 남긴다. 기간이 맞는 날짜별 운영정보를 정규 요일표보다 우선한다.
- 오사카성·가이유칸에서만 **공식 정보 확인** 버튼으로 Responses API의 `web_search`를 실행한다. 일반 조회·일정 생성은 새 웹 검색을 실행하지 않는다.
- 지정 공식 도메인, 서버에서 다시 읽은 공식 원문, 인용문을 대조한다. 확인되지 않거나 충돌한 정보는 일정 제약으로 쓰지 않는다.
- 오사카성 공식 안내의 이름 붙은 운영시간·최종 입장·연말연시 휴관 기간은 매번 실제 원문을 읽어 추출한다. 시간·휴관일을 미리 심은 관광지 데이터로 대체하지 않았다.
- 일반 입장권과 단체·감면·프로그램의 적용 범위를 구분한다. 일반 홈페이지와 공식 사이트에서 링크된 검증된 티켓 판매처를 구분한다.
- 확인된 날짜의 운영·휴관·최종 입장만 **다음 일정 생성**에 반영한다. 검색 결과로 기존 초안을 무조건 변경하지 않는다. 불가능한 필수·지정 방문은 삭제하지 않고 경고한다.
- 검색 성공 캐시 6시간, 오류 캐시 1분, 동일 요청 동시 실행 합치기, IP별 10분당 3회 및 서버 전체 시간당 30회 제한. 메모리 캐시이므로 서버 재시작 시 초기화된다.
- 서비스명 피플랜, 설정 화면의 보딩패스 카드·푸른 버튼·야간 오사카성 이미지·모바일 배치 적용. Figma 직접 화면은 접근하지 못했으며, 사용자가 첨부한 실제 이미지 파일과 설명을 사용했다.

## 자동 검증

- 백엔드 및 프런트엔드 TypeScript 검사 통과.
- 기존 일정 합성 회귀 6개 PASS.
- 신규 공식 출처·위장 도메인 거부·인용문·종료/입장 구분·연말연시 휴관·날짜/범위/만료/충돌·제공자 오류 관련 합성 테스트 6개 PASS.
- 신규 테스트는 generated package의 확장자 없는 import 때문에 먼저 esbuild로 번들한 뒤 Node test로 실행한다.

## 실제 연결과 한계

- Google Places / Routes / Static Maps / 사진: 실제 성공 응답 확인. 서버 프록시를 사용하며 브라우저에 키를 전달하지 않는다.
- OpenAI Chat Completions: 기존 요청 해석 모델 `gpt-4o-mini` 실제 성공.
- OpenAI Responses: 공식 검색 모델 `gpt-5-mini` 및 `web_search` 실제 성공. 실제 연결 성공과 모든 관광 정보의 검증 완료는 다르다.
- 임시 공지 누락, 미래 월별 달력, 예약 잔여석, 운영자 웹페이지 변경까지 보장하지 않는다.
- 공식 원문 구조가 바뀌거나 원문 인용 대조에 실패하면 확인 필요를 유지한다. 예약 오픈 규칙에서 임의로 마감 날짜를 계산하지 않는다.
- 저장 복원은 기존처럼 **사용자 입력**의 브라우저 저장이다. 공식 검색 결과의 영구 저장이나 서버 재시작 간 보존은 구현하지 않았다.

## 브라우저 회귀

PC·모바일의 추가 시안이 도착해 기존 브라우저 검증은 중단 시점 결과만 기록했다. 이 문서의 API PASS를 새 디자인의 브라우저 전체 PASS로 간주하지 않는다.

- **PASS, 새 시안 적용 전:** 날짜 11/16–11/18, 20% 설정, 6곳 선택, 실제 Google 운영시간·공식 홈페이지 표시.
- **PASS, 새 시안 적용 전:** 공식 검색 버튼 1회로 HTTP 200·약 36.9초. 실제 검색·공식 시간·입장 마감·예약 선택·출처 표시. 검색 후 STEP 2 유지, 자동 생성·이동 없음.
- **PASS, 새 시안 적용 전:** 새로고침 후 날짜·20%·6곳 선택 복원.
- **표시 문제 수정:** 정기 휴관 규칙의 ‘적용 날짜’가 실제 휴무 날짜처럼 오해될 수 있다는 관찰에 따라 ‘검토한 여행 날짜’와 실제 해당 휴관일을 구별했다. 해당 여행 기간에 정기 휴관이 없을 때도 명시한다. 확인 시각은 브라우저 시간대 대신 KST로 표시한다.
- **미실행:** 브라우저에서 필수 2곳의 시간 지정·생성·마커·체류/순서 수정까지의 전체 흐름은 중단되어 완료하지 못했다. 같은 기능의 위 API 회귀는 PASS.
- **미실행:** 브라우저에서 503 응답 주입. 백엔드 합성 오류 테스트만 PASS이며 실제 외부 장애 시험이 아니다.

## 추가 PC·모바일 시안 반영

- 이후 첨부된 PC 4개·모바일 4개 화면을 기준으로 같은 네 단계를 다시 스타일링했다.
- PC는 모든 단계에 39% 너비의 왼쪽 오사카성 패널과 가로 진행 표시를 유지한다. 모바일은 첫 설정 단계에만 이미지 배너를 보여 준다.
- 보딩패스형 2×2 입력, 장소 검색·선택 칩, 모바일 가로 장소 카드, 방문 조건의 반응형 입력 배치, 결과의 날짜 탭을 적용했다.
- 1440×1000 PC 및 390px 모바일 전체 페이지의 실제 설정 화면을 캡처해 레이아웃과 정상 렌더링을 확인했다. 새 시안의 나머지 세 단계는 전체 브라우저 회귀를 다시 실행하지 않았다.
- 백엔드·프런트엔드 TypeScript 검사와 공식 정보 합성 테스트 6개를 최종 변경 후 재확인했다.

## ‘처음부터 다시’ 확인 모달

- 브라우저 기본 confirm을 제거하고 현재 UI와 맞는 흰색 카드·파란 버튼의 접근 가능한 Dialog로 변경했다.
- 열기·취소·X·Esc·바깥 영역 닫기는 초기화 함수를 실행하지 않는다. 기본 초점은 ‘취소’에 둔다.
- ‘처음부터 시작’을 확인해야 날짜·장소·방문 조건·초안이 초기화된다. 초기화 후 늦게 도착하는 이전 AI 응답도 적용하지 않도록 요청 세대를 확인한다.
- 프런트엔드 TypeScript 검사를 통과했다.
- **실제 브라우저 PASS:** 열기만 할 때 데이터 유지, 취소·Esc·X로 닫을 때 데이터·초안 유지, 확인 후 날짜·선택·필수·방문 조건 초기화 및 첫 단계 이동.
- **실제 모바일 PASS:** 390px에서 모달 너비 358px, 가로 넘침 없음. 취소·확인 버튼 높이 44px. 초기화 후 빈 날짜·50%·빈 선택 확인.
- **발견 후 수정:** 기본값만 저장돼 있어도 복원 배너가 뜨던 문제를 의미 있는 입력이 있을 때만 표시하도록 바꿨다. X의 터치 영역을 44×44px로 키웠다. 두 단순 수정은 코드·타입 검사로 확인했으며 전체 브라우저 시험을 반복하지 않았다.
